# 检索与阅读的协作流程

以下参数对象交给当前发现的同名 MCP 工具；示例 URL 与编号仅用于说明。按缺口选择环节，不把示例固化成每次必跑的流程。示例省略项目标签；当前 schema 支持时，按 Skill 的项目规则随调用补充 `project`。

## 网页调查：发现 → 选择 → 阅读

将问题拆成能改变结论的子问题，查询保持聚焦。比较来源时可先调用：

```json
{"query":"Go 泛型 性能 基准","time_range":12,"fetch_top_n":0}
```

`fetch_top_n=0` 关闭额外补抓，供应商仍可能自带长内容。若希望直接阅读少量候选，可以设 `fetch_top_n: 2`；它对最终列表前两项补抓，不保证这两项就是最适合引用的来源。

检查来源、发布日期、版本和内容。针对选中的 URL 调用 `cleanfetch`；批量时 `url` 放第一项，`urls` 放其余项，合并去重后最多五项：

```json
{"url":"https://go.dev/doc/tutorial/generics","urls":["https://go.dev/ref/spec"]}
```

逐节检查成功、失败和 `result_ref`；已保存正文用 `cleanfetch` 按 `next_offset` 分段读取。足量正文直接复用；搜索摘要不足、自动补抓跳过或失败时，才继续抓指定页面。正文中有 PDF、DOI 或 arXiv 编号时转入论文流程。

时间范围是检索提示，不是统一的精确日期过滤；历史问题需要目标年份或版本查询、日期核验及覆盖不足时的其他检索来源。详见运行行为。

v3.6.2 起先检查 `retrieved_at`、可选的 `cache_age_seconds`、日期来源及响应尾部失败清单。`snippet` 日期不是出版日期证据；低结果数的 `filter_diagnostics` 提示过滤或阈值放宽，不等于数据库里没有资料。整体结果落盘时先用候选预览筛选，需要原文时通过 `cleanfetch` 读取，再判断证据。

## 论文调查：主题 → 身份 → 全文

按当前工具列出的可用引擎选子集，例如：

```json
{"query":"retrieval augmented generation evaluation","engines":["arxiv","openalex"],"time_range":"year","page":1}
```

医学可优先 PubMed、Europe PMC，计算机可优先 arXiv、DBLP、Semantic Scholar，跨学科可用 Crossref、OpenAlex；这些是起点，覆盖不足时再扩展。省略 `engines` 会使用全部启用引擎，不意味着每个引擎都成功。

学术结果通常是摘要和元数据。排名融合了引擎顺序、引用数、期刊和 PDF 等信号，并非论文质量评审；核对研究对象、文献类型、版本和日期。

已找到编号时，让整个查询仅包含编号或规范编号 URL：

```json
{"query":"arXiv:1706.03762"}
```

```json
{"query":"10.1038/s41586-020-2649-2"}
```

这会走单篇精确查询，忽略 `time_range/page`，仍遵守来源开关与指定 `engines`。题名与编号不匹配时先处理身份问题，不将不同版本或同名论文的内容拼接。

取得结果后的下一步：

| 返回内容 | 下一步 |
|---|---|
| 直接 PDF 地址 | 将实际返回地址传给 `pdf_parser.path`。 |
| DOI/出版商/机构库落地页 | 用 `cleanfetch` 读取摘要、版本及全文入口；有 HTML 全文可直接阅读。 |
| `PDF` 字段实际返回 HTML | 检查该页是否是全文；否则用 `cleanfetch` 提取真正的下载链接。不要靠添加 `.pdf` 猜地址。 |
| 缺少 PDF 或失效链接 | 用题名加作者、DOI/arXiv 编号进行 `smartsearch`，找公开版本并核对身份；未找到时如实限定为摘要层证据。 |
| 部分引擎失败 | 先利用成功结果；需要该领域覆盖时再重试相应引擎或补充其他来源。 |

不需要对每篇主题结果重复精确查询；它适合消歧、补元数据或核对编号。

## PDF：选页 → 核对范围 → 提取证据

使用实际取得的 PDF 链接，例如：

```json
{"path":"https://arxiv.org/pdf/1706.03762v7","pages":"1-3"}
```

页码是文件的 1-based 页序，不一定等于论文印刷页码。按问题读取有关部分；请求全文时持续读取剩余范围，不能停在默认前二十页却声称已读完整篇。

v3.6.1 起，原件超页或 URL 被拒时可以裁切后分批上传。页限、每批大小和单次预算是服务端配置，不是工具参数；预算按整批准入，剩余额度不足下一批时可提前停止。检查实际已解析范围及续读页码，再请求缺失部分。进度通知不是解析正文，也不证明所有批次成功。

查看选页和截断提示。MinerU 精准 API 的 Markdown 可能引用 ZIP 内的相对图片，需用结果中的完整 ZIP 取得图片；轻量 API 仅提供 Markdown。没有提示也要检查是否实际得到 PDF 正文，而非 HTML 登录页、落地页或错误页面。

检查空白、英文粘连、图表引用、公式与数值。需要视觉证据时使用可用的 PDF 渲染/阅读能力补充。提取质量差但非空不会必然触发服务端 OCR；当前参数没有强制选择解析器或 OCR 的开关。 未发现可用的补充阅读工具时，交付已核验内容并明确表格或公式未验证；若缺失证据是回答问题的必要条件，应说明任务尚未完成及所需的最小补充材料。

## 本地资料：定位 → 阅读

仅在当前工具清单含 `file_search` 时使用，例如已授权范围内找 PDF：

```json
{"query":"ext:pdf thermoacoustic","folder":"D:\\Research","max_results":10,"page":1,"time_format":"datetime"}
```

`folder` 按任务需要指定目标目录，不受当前对话所属项目限制；省略时搜索全部已索引文件。部署若配置了非空 `everything.roots`，需遵守其目录限制。查询支持 Everything 通配符和 `ext:/dm:/size:` 等语法，不是语义全文搜索。默认每页 10 条，硬上限 20；保留同一查询和页大小，用 `page` 翻页（上限 100），深页受 600 条候选池限制，必要时收窄查询。找近期改动可设 `sort: "date_modified", descending: true`；复杂匹配参数详见运行行为。

检查实际路径、过滤后的条数及分页提示；命名相似不证明内容相关。工具缺失时用已有宿主文件搜索，不自行安装 Everything、开放 HTTP 或扩大白名单。

选定 PDF 后按文件实际可见位置阅读：

1. 确认用户选定的具体文件、当前宿主与 WebSearch 服务的位置。`file_search` 返回的是索引宿主路径；服务在 Docker 中时，Windows 路径不等于容器路径。
2. 先检查 PDF 附近的同名 Markdown、同名解析目录及 `source/` 与 `md/` 的对应资料；需要扩大定位时在相关资料目录内用文件检索。结合当前问题抽查正文、图表公式和覆盖范围，认为够用就原位复用旧资料，不因缺少机器记录而强制重解析。
3. 少量查阅可用宿主 PDF 阅读或离线提取。需要完整阅读或保存解析资料且旧资料不够时，调用本地 `pdf_parser`；新 schema 支持本地精准归档时省略 `pages` 以整本为目标，按[本地精准归档](runtime-behavior.md#本地精准归档)自动接续。
4. 远程或 Docker 服务无法读取宿主文件时，先用宿主阅读工具。确需容器解析且已有单文件复制授权时，才按[运行行为的文件可见性小节](runtime-behavior.md#文件可见性原生与-docker)临时复制、读取并清理；原生服务不需要这一转换。

复制进容器不等于上传外部服务。配置 MinerU Token 的本地精准归档会上传待处理页面，关闭 OCR 并不关闭上传；旧部署也可能有 OCR 上传回退。私密资料只有在允许相应外部处理时才采用这些路线，否则使用宿主离线阅读。`pages` 选择范围，不控制上传开关。

## 失败后的有意义转换

| 当前状态 | 下一步依据 |
|---|---|
| `smartsearch` 正文补抓失败 | 对关键 URL 尝试 `cleanfetch`，它额外具有配置相关的 Jina 回退；仍失败则换原始来源或公开版本。 |
| 学术无结果 | 调整题名/编号/学科引擎；需要时由模型主动转 `smartsearch` 找出版商、机构库或作者页面。 |
| 429 或暂时超时 | 保留已有结果，依据限流提示延后或缩小请求；服务器已自带部分重试，避免紧密重复。 |
| 登录、WAF、404 | 查可访问的权威替代入口；不要把未获取的正文描述为已核验。 |
| 大内容落盘 | 将 `result_ref` 传给 `cleanfetch`，按 `next_offset` 续读到所需内容或 `eof=true`；失效后才重新调用原工具。 |
| 内网地址被拒、宿主文件不可见 | 使用任务允许的宿主阅读或已配置访问方式，不修改防护或挂载来绕过。 |

补充工具应解决具体缺口。同一原文被多个引擎收录、换抓取器读同一页面，都不算新增独立来源。
