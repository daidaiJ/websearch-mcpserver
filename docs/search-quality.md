# 搜索质量基准与参数调优

> 2026-11-17。本基准受开源项目 [`fangchenghao/dsh-web-search`](https://github.com/fangchenghao/dsh-web-search) 的公开评测集启发，沿用其 MIT 许可的 20 条中英 query 与真实引擎快照，通过本项目的评分管线重放。本文记录基准口径、默认配置的实测效果、各参数的方向与置信区间，以及用户在自己的历史数据上调优的设计。

## 1. 数据集

- 来源：[`fangchenghao/dsh-web-search`](https://github.com/fangchenghao/dsh-web-search)，commit `0b7d1e42f5c965b0f46dc7f7cadb03302b041cdb`（npm `0.24.2`，MIT）。
- 内容：20 条 query（10 中 / 10 英；docs / release / package / news 各 5 条），每条 1–3 个 expected domain；每条 query 保存 5 个引擎的原始结果列表（anysearch / exa / firecrawl / ddg / bing，每个引擎最多 10 条）。
- 存放：`bench/tuning/testdata/dsh-web-search/`；许可与改动说明见同目录 `LICENSE` 与 `NOTICE.md`。
- 重放：不触网、不走缓存，直接把这批原始排名喂给 `pkg/search/enhance`，所以任何权重/阈值改动都能得到可复现的指标差。

## 2. 指标与统计口径

| 指标 | 定义 |
|---|---|
| `P@8` | top-8 中命中 expected domain 的结果行数 / 8（固定分母；结果不足 8 条也按 8 算） |
| `R@8` | top-8 覆盖的 distinct expected domain 数 / expected domain 总数 |
| `MRR@8` | 首个命中结果的排名倒数；无命中记 0 |
| `ΔMRR [95% CI]` | 候选配置相对默认配置的配对 bootstrap（4000 次重采样，seed 42）；同一 query 同时参与两侧，抵消 query 难度 |
| `W/L/T` | 逐 query 的 MRR 胜/负/平局数 |

域名匹配是单向的：expected `python.org` 覆盖 `docs.python.org`；expected `docs.python.org` 不覆盖 `python.org`。

**读法**：20 条 query 的统计功效很低，置信区间跨 0 时不要解读为“有提升”。本文把“显著”限定为 95% CI 不跨 0；其余只写方向性。

## 3. 运行

```bash
# 默认使用内置公开参考集，输出 Markdown 表
go run ./bench/tuning/cmd/searchbench

# 更稳定的区间 + 写入文件
go run ./bench/tuning/cmd/searchbench -iterations 4000 -format md -out report.md

# 用自己的回放目录（queries.json + fixtures/）
go run ./bench/tuning/cmd/searchbench -data ./my-capture -dump dataset.json
```

JSON 输出用 `-format json`。`-dump` 把归一化后的数据集写出来，便于检查或二次编辑。

## 4. 默认配置基线

生产默认：RRF K=60、词汇对齐权重 0.5、共识/权威/新鲜度/域名品质/稀有词倍率均为 1、阈值 0.05、MMR 开启 λ=0.7、top-8。引擎权重取快照记录的权重（anysearch 2，其余 1）。

| 配置 | P@8 | R@8 | MRR@8 |
|---|---:|---:|---:|
| 本项目评分管线（快照权重） | **0.6625** | **0.7917** | **0.8750** |
| `dsh-web-search` 0.24.2 自评（`node scripts/bench.mjs`，同批 fixture） | 0.4375 | 0.7917 | 0.8071 |

`dsh-web-search` 的数字由其仓库 0.24.2 的 `node scripts/bench.mjs` 离线重跑得到（tier-aware 回放；本批快照的五个引擎都标为 primary，因此与本文直接喂入全部引擎的口径一致）。两组数字不是同一排序器的横向对比：本项目在 RRF 之外叠加了域名品质、权威性、词汇对齐与稀有词信号，而这批 query 以官方文档/发布说明为主，正好落在权威性加分的覆盖范围。把它当作“同一数据集上的两套管线参照”，不要当作通用质量结论。

权威性加分在 2026-11 扩展了“数据/统计”意图门控：查询命中 GDP / 人口 / 普查 / 统计 / 指标 / 数据集等信号时，`.gov`、`.gov.cn`、世界银行、IMF、OECD 等官方一手源获得额外加分；非数据查询不受影响。该分支可用 `smartsearch.primary_source_boost: false` 关闭。本节的 20 条 query 以技术文档为主，未覆盖该分支。

## 6. 结论与建议

1. **默认配置保持不动**。唯一显著的效果是“关掉权威性加分会变差”，其余参数在这 20 条 query 上要么无差异，要么 CI 跨零。该项目的公开结论同样是“语料分辨不出差异，默认不改”。
2. **想调时优先动这两个**：
   - `smartsearch.mmr.lambda`：想要更多样的结果降到 0.5 左右，接受 P@8 下降；想要更贴题升到 0.9。
   - `smartsearch.relevance_threshold`：想更严可以小幅升到 0.1；0.2 已经开始掉召回。
3. **不要在小样本上追 RRF K / 引擎权重**。本集 K=80/120 方向性更好，但 CI 触零且只影响 1–2 条 query；该项目的 K=40 扫描同样跨零。换一批 query 方向可能反转。
4. **权威性、共识、词汇对齐是默认保留项**。本集没有证明它们“越大越好”，但关掉权威性明确有害；共识关闭方向性变差；词汇对齐关闭在本集不降，但对非文档类 query 缺少证据，保持 0.5。
5. **这批 query 偏官方文档/发布说明**，对权威性和域名品质天然友好。新闻、论坛、中文社区类 query 需要用户用自己的历史数据重跑，不能直接套用本集结论。

## 7. 在自有历史数据上调优（设计，待拍板）

目标：让 agent 用用户自己的 query/引擎分布跑同一套 sweep，而不是拿 20 条公共 query 猜配置。

**采集层（默认关闭）**

- 新配置 `search_eval.capture_raw: true`（零值关闭）时，在 `hybrid.mergeResults` 调用 `enhance.EnhanceResultsMMR` 之前，把本次的 per-engine buckets 写入本地 `history/search-eval.db`：引擎名、rank、title、url、snippet、publish_date、query、时间戳。
- 只在本机落盘，不联网、不带密钥；保留期默认 30 天，随 `search_history` 的后台清理一起删；关掉开关即停止写入，删库即清除。
- 隐私边界比现有 `search_history` 更敏感（含 URL/摘要），所以必须独立开关、独立库、文档写清；不默认开启。

**导出与回放**

- `websearch-mcpserver tune export --since 30d --out ./my-capture` 把历史记录写成与参考集相同的 `queries.json + fixtures/*.json` 结构（或本文的归一化 JSON）。
- agent 直接运行 `go run ./bench/tuning/cmd/searchbench -data ./my-capture`，得到逐参数 P@8/R@8/MRR@8、ΔMRR 置信区间与 W/L/T；据此提出配置 diff，由用户确认后再改 `config.yaml`。
- 不新增 MCP 工具：调优是低频运维动作，CLI 已能被 shell 型 agent 调用，避免把常驻工具面从 5 个扩到 6 个。若未来 Docker/stdio 用户无法执行 shell，再评估默认关闭的 `search_eval` 工具。

**验收**

- 采集单次开销 < 1 ms，失败不影响搜索主链路；
- 断网可回放；导出文件可人工检查；
- 删除 `search-eval.db` 后搜索行为不变；
- 文档给出采集开关、保留期、导出命令与“改配置前先备份”的提示。

## 8. 局限

- 20 条 query 的配对 bootstrap 只能识别较大效应；本文不宣称“最佳配置”，只宣称“默认配置在这批数据上没有明显退化”。
- 回放集是该开源项目在 2026-10 抓取的真实引擎快照，排名会漂移；它适合回归与参数方向判断，不适合作为长期绝对分数。
- 本项目的权威性/域名品质信号对官方文档有结构性偏好；跨语种、新闻、论坛类 query 需要自有数据验证。
- `recency` / `domain_quality` / `rare_terms` 在本集无可测差异，不等于在其他分布上无效。
